Работающий **user-mode прототип (v9-min)** с сильной надёжностной частью и дисциплинированным журналом. Это **не продукт и не «90 %+ защита»**.

| Цель эффективности (ядро, E1–E6 ≥90/70 %) | ≈ 0 % (заблокировано внешними факторами, не кодом) |

## 6. Независимый ИИ-ревью: возможно ли и как

### 6.1 Да, но с условиями

Сторонний ИИ-агент **может** быть дополнительным гейтом, но **не заменяет** human-review для уровня C (драйвер/ядро/политика) — это прямо записано в `docs/auto-reviewer-spec.md`.

### 6.2 Что сторонний ИИ-ревьюер реально может

- Перепрогнать тесты и регрессию **независимо** и сверить числа с артефактами.
- Проверить контракты, дрейф схем, immutable-политику.
- Найти противоречия «DEVLOG ↔ артефакты ↔ код».
- Прогнать статический анализ, линтеры, `cargo clippy`, поиск `shell=True`/`eval`/небезопасных подпроцессов.
- Проверить семантику правил по AST/данным (что правило действительно матчит технику).
- Проверить fail-safe и роли IPC на тестах.

### 6.3 Что сторонний ИИ-ревьюер НЕ может

- Дать семантическую гарантию корректности Windows-minifilter / Linux-LSM на уровне ядра.
- Подтвердить runtime-поведение на реальных ОС без VM/железа.
- Заменить human-подпись для драйвера (уровень C).
- Доказать эффективность E1–E6 — это только red-team.
- Гарантировать отсутствие скрытых дефектов в модели/данных.

### 6.4 Как проводить правильно (изоляция)

1. **Другая модель** (`reviewer_model != author_model`) и **другой промпт**; `temperature=0`.
2. **Без доступа к контексту автора** — отдельный свежий запуск (не fork текущей сессии).
3. **Только чтение кода + прогон тестов**; менять код ревьюер не должен.
4. Результат — в DEVLOG как `auto_review` с `run_id`, замечаниями и вердиктом `approve / request_changes / escalate`.
5. При расхождении с автором — **эскалация человеку**, а не «переголосование» ИИ.

### 6.5 Как запустить (практически)

Отдельный субагент с другой моделью получает:
- путь к репозиторию;
- чек-лист §5 (P0/P1);
- команды для самостоятельного прогона;
- запрет менять код;
- требование вернуть структурированный вердикт (что проверено / что не сошлось / что не удалось проверить).
