## 2. Как проверить одной командой

```powershell
python scripts\run_all.py            # 22 шага: тесты, правила, схемы, immutable, артефакты,
                                     # Windows-полосы, Linux-полосы (WSL), T1055-матрица,
                                     # согласованность документов, итоговый срез
python scripts\run_all.py --with-soak --soak-seconds 300   # плюс soak
```

Результат: [artifacts/run_all.json](../artifacts/run_all.json) и сгенерированный [docs/status.md](status.md).

## 3. Что построено

Двухконтурная архитектура: детерминированный рефлекс (правила, <5 мс) и «когнитивный» советник за политикой, с fail-safe по умолчанию.

| Слой | Модули | Назначение |
|---|---|---|
| L0–L1 | `core/ingest.py`, `core/pipeline.py`, `core/normalize.py` | приём без потерь, приоритеты, нормализация 9 источников |
| L2–L3 | `core/rules.py`, `rules/base.json`, `core/coverage.py` | правила как данные, окна, корреляция, покрытие ATT&CK |
| L4 | `core/gate.py`, `core/confirm.py` | политика severity→действие, бюджет алертов, подтверждение |
| L5 | `core/response.py`, `core/appcontrol.py` | обратимые действия: suspend/resume, карантин AES-GCM |
| L6 | `core/modelpack.py`, `core/ml.py`, `core/calibration.py`, `core/model_registry.py` | подписанные ONNX-модели, fail-closed, калибровка, реестр ролей |
| L7 | `core/ipc.py`, `core/daemon.py` | JSON-RPC (pipe/AF_UNIX), роли, health/stats |
| L8 | `core/selfprotect.py`, `core/safemode.py`, `core/updater.py`, `core/watchdog.py`, `core/heartbeat.py`, `core/counters.py`, `core/clock.py`, `core/negotiation.py` | аудит-цепочка, safe mode + LKG, dual-slot, watchdog×2, heartbeat+проба, счётчики, монотонные часы, capability negotiation |

Источники событий: Windows `System`/`Defender/Operational` через `wevtutil`; Linux eBPF (`sched_process_exec`, LSM `file_open`/`file_mprotect`, `connect4`, `process_vm_writev`, `ptrace`) через libbpf в WSL2.

## 7. Границы и гарантии

- **Драйвер/ядро не писались**: нет EV-подписи и WDK; спайк 5 остаётся открытым, M10=0 %.
- **Immutable-константы не тронуты** (`FAIL_SAFE_ON_TIMEOUT`, `MODELS_TRAIN_ON_DEVICE`, `DRIVER_SIGNED_BY_HUMAN`, `KERNEL_CODE_REVIEW_REQUIRED`), fingerprint стабилен, проверка в прогоне.
- **Обучения на устройстве нет**: модели обучаются офлайн-скриптами, рантайм только проверяет подписанный пак и делает инференс.
- **Модель в shadow**: v2 подписана и проверена, но в политику не включена; champion-слот пуст, промоушен — только человеком.
- **Реестр моделей** требует подписи пака для регистрации и человека для `champion` (проверено тестом).
- **Обратимость**: разрушительные действия требуют оператора; карантин обратим; при таймауте подтверждения — отказ (fail-safe).

## 8. Что НЕ доказано

1. **E7**: 0,95 @0,05 % FPR не достигнута (0,6724); рост упирается в статику — нужен кросс-модальный ансамбль.
2. **R1/R4**: 5-минутный soak с плато, не сутки; «≤1 %/сутки» не опровергнуто и не доказано.
3. **Windows T1055**: ETW-TI требует элевации (блокер D).
4. **Драйвер/ядро**: нет подписи, WDK и human-review.
5. **Эффективность против реального adversary**: матрица покрытия — отображение техник, не red-team.
6. **Калибровка на развёртывании**: разрыв confidence против PPV при корректном prevalence-взвешивании — 0,0397 в худшей точке (0,1 % FPR); ранее заявленные 0,3964 оказались ошибкой сравнения; для PPV остаётся расчёт по TPR/FPR.
7. **Провенанс**: работает из ядра, но обход ограничен 8 компонентами и 15 символами; allowlist путей — не подписи/IMA.

## 11. Воспроизведение

```powershell
python -m pytest                                     # 538 passed, 1 skipped
python scripts\run_all.py                            # 22/22
```

## 12. Ограничения этого отчёта

## 14. Открытый блокирующий дефект: нативный краш на длинных прогонах

| Факт | Значение |
|---|---|
| Симптом | `0xC0000005` (access violation), процесс умирает без Python-исключения |
| Где наблюдалось | t≈479 с и t≈238 с в прогонах разной длины; **1 из 4** в кампании 600 с |
| Что показывает стек | в одном дампе — `Event.model_validate` ← `Pipeline.run_once`; в другом main в `sleep` |
| Что исключено | деградация `health()` (127k записей — p50 1,87 мс); pydantic сам по себе (**9,94 млн** валидаций без сбоев); бисекция `no_audit`/`no_rss` (6×240 с чисто) |
| Что сделано | убрана двойная валидация, исправлена утечка дескриптора, включён `faulthandler` с дампами стеков, раннеры кампаний |
| Что это значит | **R1/R4 не подтверждены**: длинные прогоны недействительны, пока дефект открыт |

Честная формулировка: причина **не найдена**. Гипотеза о повторной валидации была проверена и опровергнута — после исправления падение повторилось. Нативный пробник показал, что fault приходит из **`python312.dll`** со стабильным смещением **0x278B44…0x278B57** (два падения в 19 байтах друг от друга), то есть на уровне интерпретатора. Интерпретатор обновлён до **3.12.9**, запущен **суточный прогон** на падающем профиле (health каждые 2 с) под супервизором; результат — в [soak_supervised.json](../artifacts/soak_supervised.json) (частями в `soak_supervised_partial.json`).

## 15. Лабораторные полигоны (13–14.11.2026)

Оба полигона подняты на Hyper-V (Gen2) и управляются с хоста: Windows — через **PowerShell Direct**, Linux — по **SSH-ключу**.

| Полигон | Факты | Что уже проверено | Что блокирует |
|---|---|---|---|
| **Windows 11** | `AIDFLAB`, Enterprise Evaluation **build 26300**, 4 ГБ / 2 vCPU, установлен **офлайн** (DISM apply + bcdboot + `Panther\unattend.xml`), Secure Boot **Off**, `testsigning Yes` | установка, вход по PowerShell Direct, попытка загрузки WDAC audit-политики | неподписанная CI-политика на 26H2 **не загружается** (`CiTool --list-policies` её не видит, 3076/3077 = 0) — нужна подписанная политика или генерация через ConfigCI внутри VM |
| **Linux** | `aidf-linux`, Ubuntu **24.04.5**, kernel **6.8.0-147**, 3 ГБ / 2 vCPU, cloud-образ (qcow2→VHDX), Secure Boot **On**, kernel **locked down** | SSH, `ima_policy=tcb ima_appraise=enforce` (**3 713 измерений**), fapolicyd (trust DB **60 737**), auditd | enforcement не измерен: пакетные правила fapolicyd — `deny_audit` (только аудит), а построение trust DB занимает **>8 мин**, и демон не доходит до прослушивания; IMA `tcb` не содержит appraise-правила, поэтому копии бинарей исполняются |

**Вывод по полигонам:** инфраструктура для блокеров B/C готова и воспроизводима, но оба «защитных» механизма упираются в подпись/политику: WDAC — в подпись CI-политики (без EV её нет на 26H2), целостность Linux — в политику fapolicyd и appraise-правила IMA. До этого цифры «blocked/denied» публиковать нельзя.
