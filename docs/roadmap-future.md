# Долгосрочное развитие и уровни поставки

> **Статус:** рабочий документ. Раскрывает v9.1 §1.3 и §13.

## 1. Уровни поставки

| Контур | Описание | Потолок эффективности | Условие |
|---|---|---|---|
| **v9-min** | user-mode (нет ядро-подписи) | ~70–80% массовые, ~20–30% целевые | пока нет доступа к подписи |
| **v9-max** | ядро-компонент + контроль приложений | ≥90% (цель) | после подписи |
| **v9-ultra** | + hardware root of trust, memory-forensics, XDR | →95%+ | долгосрочно |

Переход v9-min → v9-max бесшовный: код проектируется так, чтобы ядро-компонент подключался без переписывания (платформенная абстракция).

## 2. Горизонты

### Ближний (после релиза)
- Тюнинг suppression/allowlist, калибровка PPV в пилотах.
- Фиды: hash reputation, Sigma-правила, IoC-коннекторы.
- Расширение deception (honeytokens: фейковые учётки/ключи/конфиги).

### Средний
- Network DPI + TLS-инспекция (opt-in MITM).
- Авто-переобучение офлайн (конвейер яруса 2 полностью автоматизирован, человек — подпись).
- Облачная корреляция (opt-in), threat intel.
- Memory-forensics глубже.

### Дальний
- Hardware root of trust: TPM/measured boot, Trusted Boot.
- Глубже eBPF-руткит-детекция (kprobe/kretprobe, LKRG-подход).
- XDR-интеграция (обмен телеметрией с SIEM/SOAR).
- Self-supervised ML (обучение на неразмеченных данных).
- Формальная верификация драйвера (инварианты, модель-чекинг).

## 3. Исследовательская повестка

| Направление | Вопрос | Когда решать |
|---|---|---|
| TLS-инспекция | MITM vs TLS-fp — баланс приватности и детекции | средний горизонт |
| Federated learning | замена централизованного сервера агрегацией | только после доказанной безопасности |
| Self-supervised | обучение без разметки без отравления | дальний |
| Формальная верификация | какие инварианты драйвера доказуемы | дальний |

## 4. Точки расширения (уже заложены)

- Плагин-интерфейс детекторов/реакций; реестр моделей (shadow/canary); интеллект-коннекторы; OTel-телеметрия; версионируемые схемы + capability negotiation; API и конфиг-миграции без breaking.

## 5. Правило

Каждый горизонт активируется только при стабильности текущего уровня (метрики в целях N недель) и фиксируется `decision`. Не наращиваем функции поверх нестабильной базы.
