# STML — графический дизайн терминала

> Дизайн-спецификация для Tauri-GUI (основной) и TUI (аварийный). Полный
> интерактивный макет — [docs/stml-gui-mock.html](stml-gui-mock.html).

## 1. Принципы

1. **Тёмная SOC-тема** — оператор смотрит часами; меньше нагрузка на глаза.
2. **Плотность информации выше, чем у SaaS** — но не в ущерб читаемости.
3. **Иерархия по критичности**: красный = требует действия, жёлтый = внимание,
   зелёный/нейтральный = норма.
4. **Действия явные и обратимые**: dry-run по умолчанию, diff перед apply,
   подтверждение на необратимое.
5. **Роли управляют видимостью**: viewer/operator/admin; кнопки скрываются,
   а не «красятся серым».
6. **Zero secrets в GUI**: ключи/токены не показываются и не сохраняются; только
   отпечатки (`…7f3a`) и статусы.
7. **Клавиатура**: глобальный поиск `/`, переключение разделов `1..9`,
   approve/deny с подтверждением.
8. **Офлайн-состояние агента** видно сразу, а не через переход.

таблицу.

## 4. Экраны

### 4.1. Dashboard

- Карточки сверху: `Online / Degraded / Offline / Alerts (24h) / FP (7d)`.
- Графики: heartbeat-латентность, события/с, вердикты, бюджет алертов.
- Лента последних инцидентов с severity и переходом.
- «Что требует действия»: pending approvals, неудачные rollouts, tamper.

### 4.2. Fleet / Agents

Таблица агентов:

```
Host      OS/Arch      Version   Status      LastSeen    Policy   Alerts   Actions
prod-7f3a win/10 x64   0.1.0     healthy     2 s ago     v12      0        …
lab-01    linux x64    0.1.0     degraded    61 s ago    v11      2        …
edge-9c   win/11 arm64 0.1.0     offline     4 min       —        —        …
```

Колонки настраиваются; сортировка, фильтр по статусу/ОС/каналу; массовые
действия только с dry-run и подтверждением.

**Деталь агента (drawer):** capabilities, процессы, версии правил/моделей,
health-состав (heartbeat/probe/queue), `trace_id`, последний report, кнопки
`Suspend / Quarantine / Kill-switch`.

### 4.3. Policies

- Список политик с версиями и каналами (`stable/canary/beta/pinned`).
- **Diff** политик (двухпанельный, моноширинный).
- `Dry-run` по набору агентов → отчёт «что изменится», затем `Apply`.
- Immutable-поля помечены замком; изменение → human-approval.

### 4.4. Rollout

- Прогресс-бары по каналам: `canary 1% → 10% → 50% → 100%`.
- Кнопки `Halt`, `Rollback`, `Promote`.
- Таймлайн этапов с таймстемпами (метрика S3).

### 4.5. Trust / Approvals

- Очередь `pending` с diff и метаданными (что меняется, кем предложено).
- Кнопки `Approve` / `Deny` / `Request changes`; для драйвера — 2-person.
- Audit-цепочка: неизменяемый журнал, экспорт в SIEM.

### 4.6. Learning

- Приём телеметрии (объём, PII-фильтр, квота).
- Очередь кейсов → курирование → разметка → обучение → регрессия → подпись.
- График «реально учится»: TPR@FPR, MTTD, FP-бюджет.

### 4.7. Reports / Incidents

- Приоритетные очереди P0–P3; P0 в отдельной ленте.
- Таймлайн инцидента: события → вердикты → действия → подтверждения.

### 4.8. Modules

- Реестр модулей: включено/выключено, версия, права (capabilities), изоляция,
  подпись. Включение — с подтверждением и audit.

### 4.9. Settings / Ops

- API enable/disable (deny-by-default), keys/HSM status, retention, SIEM.
- SLO-панель: S1–S15, error budget.

## 5. Компоненты

| Компонент | Поведение |
|---|---|
| `FleetTable` | виртуализация, пагинация, множественный выбор |
| `PolicyDiff` | side-by-side, подсветка добавлений/удалений |
| `RolloutProgress` | каналы + halt/promote/rollback |
| `ApprovalCard` | diff + approve/deny, подтверждение |
| `IncidentTimeline` | цепочка событий по `trace_id` |
| `KillSwitch` | одна кнопка + подтверждение + TTL |
| `StatusBadge` | healthy/degraded/offline/tamper |
| `HealthPanel` | heartbeat, probe, queue, ledger |

## 6. Состояния

- **Loading** — скелетоны, не спиннеры.
- **Empty** — пояснение, что включить/настроить.
- **Error** — код ошибки, `trace_id`, кнопка «повторить».
- **Offline backend** — баннер, read-only кэш последних данных.
- **Agent offline** — последнее состояние + `last_seen`, действия disabled.

## 7. Доступность

- Контраст ≥ 4.5:1 (WCAG AA); фокус-визуализация; текстовые метки у иконок.
- Дальтоникам не только цвет: статусы дублируются иконкой/текстом.
- Все разрушающие действия требуют повторного подтверждения.

## 8. Технология

- **GUI**: Tauri 2 (Rust backend) + React/Svelte + Tailwind/design tokens.
- **TUI**: `ratatui` (Rust) — те же данные через API, те же роли.
- **Безопасность рендера**: CSP, без `unsafe-eval`, секреты только в OS
  keychain, mTLS-сертификат клиента.
