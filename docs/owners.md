# Владельцы STML (owners)

> Назначение фиксируется письменно (email/тикет/ADR), не устно. Каждый владелец —
> блокер соответствующего гейта.

## Подтверждённое назначение (по умолчанию, до отдельного кадрового решения)

| Роль | Назначение до | Кто назначает | Имя/должность (подтверждено) |
|---|---|---|---|
| **Владелец проекта** (CEO / владелец бизнеса) | S0.0a | совет директоров / инвесторы | **Заказчик (вы)** |
| **PM** | S0.0a | владелец проекта | **Заказчик (вы)**, до отдельного PM |
| **Владелец агента** (владелец v9.1) | S0.0c | владелец проекта | **Заказчик (вы)** (владелец v9.1) |
| **Владелец Agent Connector** (T1) | S0.1a | PM + security engineer | **AI-агент (временно), под human-approval заказчика** — до найма senior security engineer |
| **Security engineer** | S0+ | владелец проекта | **AI-агент (временно), под human-approval заказчика** — до найма senior security engineer |
| **ML-инженер** | S4 | PM | **AI-агент (временно), под human-approval заказчика** |
| **DevOps** | S7 | PM | **AI-агент (временно), под human-approval заказчика** |
| **Оператор** | S1+ | PM | **Заказчик (вы)** |
| **Юрист / DPO** | финал (DPIA) | владелец проекта | `[Имя, должность]` — привлекается в финале |

## Правила

- «Назначить» = письменное решение, записанное здесь (кто, когда, кем назначен).
- Пока роли исполняет AI-агент — каждая операция уровня human-подписи (approve, merge, подпись) требует подтверждения заказчика.
- Эскалация: A/A' 48 ч → владелец проекта ≤72 ч.
- Владелец проекта недоступен >72 ч → гейт блокируется, фиксируется в audit.
- Separation of Duties: одна учётка — одна роль; Admin ≠ Approver; Approver ≠ kill-switch.
