# Контур самообучения (learning loop)

> **Статус:** норматив, ссылается на v9.1 §8.
> **Назначение:** безопасный цикл, в котором система «учится на атаках» без обучения весов на устройстве. Три яруса + серверный конвейер + защита от отравления + метрики «реально учится».
> **Инвариант:** `MODELS_TRAIN_ON_DEVICE = False` (immutable). На устройстве веса не меняются никогда.

## 1. Обзор

```
ЯРУС 0: локальная адаптация (без изменения весов) — на устройстве
ЯРУС 1: локальная память подтверждённых кейсов (добавление, без весов) — на устройстве
ЯРУС 2: флотское обучение через сервер (веса/правила/примеры) — офлайн, подписанные
```

Каждая отражённая атака → кейс в память (ярус 1) + телеметрия на сервер (ярус 2) → следующая подписанная версия модели/правил/знаний у всего флота.

## 2. Ярус 0 — локальная адаптация

**Что «учится»:** baseline-статистика, калибровка порогов, локальный allowlist, per-process-репутация.

| Элемент | Что делает | Безопасность |
|---|---|---|
| baseline | скользящие средние (процессы из /tmp за час, net fan-out, неудачные входы) | локально, не передаётся, сбрасывается `baseline reset` |
| калибровка порога | подстройка порога IF под распределение | не трогает веса; только порог |
| allowlist | «пользователь 2 раза разрешил X → больше не спрашиваем» | per-user, обратимо, ограничен объёмом |
| per-process репутация | частотная/поведенческая | не передаётся |

**Граница:** ярус 0 — это **настройка**, а не обучение. Код калибровки не имеет доступа к меткам и весам.

## 3. Ярус 1 — память подтверждённых кейсов

### 3.1. Источники подтверждения (доверенные)

Кейс добавляется **только** если подтверждён одним из:
- детерминированное правило (высоконадёжное);
- вердикт аналитика (человек);
- детонация в песочнице (сервер);
- согласие ансамбля (≥3 независимых детектора);
- совпадение с threat-intel (подписанный фид).

**Запрещено:** добавлять кейс по собственному высокому скору модели (самоподтверждение = цикл отравления).

### 3.2. Схема кейса и retrieval

- `CaseMemoryEntry` (см. data-model-v3): вектор признаков + вердикт + контекст + подпись.
- Retrieval: k-NN/косинусное сходство по вектору признаков; при превышении порога → мгновенный вердикт (миллисекунды) до полного прогона модели.
- Память: подписанная (целостность), ограниченная по объёму (LRU-эвикция старых кейсов), откатываемая (`memory reset`).

**Эффект:** варианты уже виденной атаки распознаются мгновенно; новые неизвестные — только после полного прогона ML.

## 4. Ярус 2 — флотское обучение через сервер

### 4.1. Поток данных

```
атака → подтверждение (ярус 1) → анонимизированная телеметрия (opt-in)
  → сервер-приёмник → курирование → разметка → детонация в песочнице
  → офлайн-дообучение (LoRA / тонкая настройка) + новые правила
    + пары «вопрос→ответ» + «задача→решение»
  → регрессия (TPR@FPR, FP-бюджет, откат-тест) → подпись → версия
  → подписанный `LearningUpdate` на устройства
```

### 4.2. Компоненты сервера

| Компонент | Назначение |
|---|---|
| Приёмник телеметрии | валидация, дедуп, анонимизация, квота |
| Песочница | детонация образцов, вердикт |
| Куратор | разметка, outlier-детекция, анти-дубликат |
| Обучающий конвейер | изолированная ВМ без сети, replay-буфер |
| Регрессор | TPR@FPR, FP-бюджет, no-regression gate |
| Подписант | HSM/CI-secret (вне агента), версия |
| Дистрибьютор | staged rollout, kill-switch, откат |

### 4.3. «Вопрос→ответ» и «задача→решение»

| Формат | Пример | Использование |
|---|---|---|
| вопрос→ответ | «что значит 4625×N?» → объяснение | RAG-база, `kb_version` |
| задача→решение (few-shot) | «процесс X из /tmp лезет в сеть» → «изолировать+объяснить» | контекст LLM при инференсе (веса не меняются) |
| задача→решение (обучающий набор) | накопленные пары | офлайн-тонкая настройка |

### 4.4. LoRA-адаптеры

Сервер обучает малый адаптер под среду/отрасль (не под одну машину), подписывает, рассылает. На устройстве — только инференс базовой модели + адаптера.

## 5. Защита от отравления

| Вектор отравления | Защита |
|---|---|
| атакующий подсовывает «обучающие» файлы | подтверждение только доверенными источниками; никакого self-confirm |
| поддельная телеметрия от клиента | сервер валидирует, дедуп, outlier-детекция |
| катастрофическое забывание | replay-буфер + смешанная выборка (старое+новое) |
| деградация FP после дообучения | регрессор: no-regression gate (FP-бюджет не превышен) |
| подмена обновления | Ed25519-подпись, версия, staged rollout, kill-switch, откат |
| самовывод модели | ярус 1 запрещает self-confirm |

## 6. Версионирование и откат

- Каждый `LearningUpdate` версионируется; устройство хранит предыдущую версию для отката.
- Staged rollout: 1% → 10% → 100% с мониторингом health/FP на каждом шаге.
- Kill-switch: отключение правила/модели/адаптера по id одним действием.
- Откат проверяется тестом: «новое обновление → регрессия → откат → состояние идентично».

## 7. Метрики «реально учится»

| Метрика | Направление | Как измеряется |
|---|---|---|
| Обнаружение новых вариантов известных атак | растёт | recall по вариантам (mutation-набор) |
| TPR на свежем holdout | растёт | еженедельный holdout |
| MTTD / time-to-contain | падает | телеметрия |
| FP-бюджет (алерты/host) | **не растёт** | жёсткий потолок |
| Откаты обновлений | **0** | staged-лог |
| Дрейф скоров | в коридоре | мониторинг распределений |

**Критерий остановки:** если после N обновлений TPR на свежем holdout не растёт, а FP стабилен — цикл не работает; `decision` о пересмотре конвейера, а не «ещё данные».

## 8. Приватность и право

- Телеметрия — только opt-in, анонимизированная (пути/имена/хэши с солью), минимизированная.
- Удаление по запросу; retention задаётся явно.
- Соблюдение 152-ФЗ/GDPR: согласие, минимизация, право на удаление, документированная цель (обучение).

## 9. Границы

- Ярус 0/1 — на устройстве, но **без изменения весов**.
- Ярус 2 — единственное место изменения весов; только офлайн, только подписанное, только с регрессией.
- На устройстве — только инференс подписанного артефакта.
