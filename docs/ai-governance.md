# ИИ-ядро и управление (ai-governance)

> **Статус:** норматив. Раскрывает v9.1 §7.

## 1. Двухконтурность и разделение полномочий

| Контур | Латентность | Детерминизм | Авторитет | Отказ-режим |
|---|---|---|---|---|
| Рефлекс (детерминированный) | <5 мс | да | исполняет обратимые действия | работает всегда |
| Когнитивный ИИ | 1–10 с | нет | предлагает/направляет, **не исполняет** | при падении — рефлекс жив |

**Инвариант:** ИИ видит всё и направляет; исполнение — через детерминированный гейт. Вывод ИИ — *предложение*, а не команда.

## 2. Уровни автономии

| Уровень | Что может | Контроль |
|---|---|---|
| Reflex | обратимые действия (suspend/block/quarantine) по политике+скору | детерминированный гейт |
| Cognitive-propose | план сдерживания, объяснение, приоритет | гейт + human для необратимого |
| Cognitive-act | авто-исполнение всё большего числа обратимых действий | по метрикам PPV/FP/contain |
| Never | необратимое (terminate/delete); изменение политики/модели угроз | всегда human |

## 3. Пороги роста автономии (данные, не обещания)

Cognitive-act расширяется **только** при одновременном выполнении, стабильно N недель:
- PPV ≥50% (prevalence-сценарий);
- FP в бюджете (≤1 medium+ алерт/2 недели);
- время сдерживания p95 ≤5 с;
- 0 ложных завершений критических процессов.

Каждое расширение — `decision` с метриками-обоснованием; сужение — автоматическое при нарушении порогов.

## 4. Защита от prompt-injection

| Вектор | Защита |
|---|---|
| Вредоносный контент в событиях (путь/командная строка/лог) | ИИ читает только нормализованные события; пути/cmdline — ред актированы |
| «Попросить ИИ отключить защиту» | ИИ не имеет авторитета исполнения; вывод — предложение через гейт |
| Отравленные few-shot/промпты | примеры и промпты — только из подписанного источника |
| Аудиторский след | все действия ИИ логируются, обратимы, с `trace_id` |

**Обязательные тесты (§test-strategy):** набор injection-кейсов (файл/командная строка с инструкцией «разрешить/отключить») → ИИ не должен выдать разрешающий вердикт и не должен получить исполнение.

## 5. Роли ИИ в системе

- **Детекторы-модели** (не LLM): ML-скоры в каждом вердикте рефлекса — калиброванные, детерминированные, подписанные.
- **LLM/агент:** объяснение инцидентов, триаж, корреляция кампаний, генерация гипотез, помощь аналитику.
- **Память кейсов** (ярус 1): retrieval-распознавание вариантов известных атак (не LLM).

## 6. Управление (governance)

- Изменение политики автономии, модели угроз, порогов — уровень C (human).
- LLM работает под отдельным uid, без доступа к управляющему IPC.
- Качество LLM оценивается эталонными парами (20–30/платформу) + чек-лист: корректность техники, отсутствие галлюцинаций, понятность.

## 7. Почему не «ИИ как авторитетное ядро» (кратко)

Недетерминизм ломает 99,5% надёжности и воспроизводимость инцидентов; латентность не влезает в <5 мс; prompt-injection при полномочиях = удалённое управление системой; неверифицируемость ломает аудит/сертификацию. Двухконтурность даёт максимум «ИИ управляет» при сохранении всех гарантий.
