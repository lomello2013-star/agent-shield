# Внешнее ИИ-ревью: GLM-5.3-Flash (OpenCode)

> **Источник:** внешний ревьюер GLM-5.3-Flash (Zhipu) через OpenCode, запуск по запросу владельца, 2026-11-13.
> **Изоляция:** другая модель/вендор (`glm-5.3-flash` ≠ автор `deepseek-v4-pro`), свежий контекст, код не менялся.
> **Статус:** общая оценка (не структурированное P0-ревью по `docs/readiness-assessment.md` §5).

## Текст отчёта

### Что это

Исследовательский прототип лёгкого EDR (Windows + Linux, user-mode): ingest → нормализация → 28 правил → gate → response с откатом, плюс self-protect, IPC, ML-контур (ONNX, shadow-режим) и «платформа надёжности» с измеримыми артефактами. Рядом — Rust-порт 12 модулей.

### Сильные стороны

1. **Культура измерений — главная ценность.** `artifacts/` + `DEVLOG.md` (385 КБ) + `docs/` (35 документов: threat model, risk register, readiness, release checklist, ADR). Каждая цифра (59.5 с тихий отказ, 110.5 мс MTTR, 0 потерь на 100k, 0.6724 TPR @0.05% FPR) имеет источник и честно помечена, где «measured», где «partially». Это редкость даже для коммерческих проектов.
2. **Честность о границах.** README прямо говорит: не production, ≈35–40% готовности, E7 не достигнута, драйвера нет, red-team не проводился. Ничего не приукрашено.
3. **Тестовая база.** 33 Python-тест-файла + 20 Rust-тест-файлов (133 Rust-теста), parity-тесты Python↔Rust, contract-тесты по 21 JSON-схеме, chaos-инъекции, soak. Запустил pytest: всё зелёное, кроме 1 теста `test_suspend_and_resume_real_process` (реальный suspend процесса не удержал запись в файл — похоже на environment-зависимость Windows, стоит проверить).
4. **Разумный стек.** Минимальные зависимости (pydantic + cryptography), изоляция ML в optional-dependencies, coverage fail_under=80.
5. **Git-гигиена в норме:** `secrets/` не в git, `target/`/`__pycache__`/venv'ы не отслеживаются, CI в `.github/`.

### Слабые места и риски

1. **Замусоренный рабочий каталог** (на диске, не в git): три venv (`313/314/314c`), `rust/target` с сотнями тест-артефактов, временные папки pip, `pytest-of-lomel`. Пора почистить и зафиксировать в `.gitignore`.
2. **Один venv сломан** — `.venv313` без pytest. Дублирующиеся окружения (три штуки) — источник путаницы «какой из них рабочий». Оставьте один, зафиксируйте в README/`requirements.lock`.
3. **Много uncommitted-изменений** — `DEVLOG.md` и ~20 JSON-артефактов изменены, но не закоммичены. Артефакты, судя по всему, перегенерируются при каждом прогоне — тогда либо закоммитьте свежий прогон, либо исключите из git и храните снапшоты релизного прогона.
4. **Скриптовая свалка в `scripts/`** — 150+ файлов, включая одноразовые `fix_cjk_typo.py`, `strip_bom.py`, десяток `update_roadmap_f11*`. Разделить: `scripts/tools/`, `scripts/migrations/`, либо удалить отработанное.
5. **Ключевая цель недостижима статикой**: E7 (0.95 @0.05% FPR) — 0.6724, и в `not_proven` это честно признано «потолком статики». Значит, следующий шаг — фичи из поведенческих источников (ETW-TI, eBPF), а не тюнинг модели. Это стратегический, а не косметический пункт.
6. **Блокеры — человеческие, не кодовые**: EV-сертификат, WDK-VM, admin-окно, Linux-VM. Пока они открыты, Windows-полоса стоит на месте.

### Вердикт

**Оценка: 7.5/10 как исследовательский прототип; ~3/10 как готовый продукт — и сам проект это знает и признаёт.**

Инженерная дисциплина (тесты, артефакты, документация, честные вердикты) — образцовая для пет-проекта такого масштаба. Главные затраты усилий сейчас — не код: (1) почистить рабочее окружение и закоммитить состояние, (2) выбить блокеры A/B/D или осознанно переориентироваться на Linux-полосу, где измерений больше всего, (3) решить стратегию по E7 — статика упёрлась в потолок.

### Рекомендации по приоритету

1. Почистить диск + один venv + закоммитить (30 минут).
2. Разобраться с падающим тестом suspend/resume.
3. 24-часовой soak на always-on VM — закрывает R1/R4 и весь статус «35–40%».
4. Стратегическое решение по E7 / переезду на поведенческие источники.

## Проверка со стороны проекта (2026-11-13)

- Утверждение о 1 падающем тесте **подтверждено**: `tests/test_response.py:177`, `test_suspend_and_resume_real_process`; на **Python 3.14 + venv** падает из-за redirector-потомка (запись `DEVLOG.md:2638`, `py314-compat`), на **3.12.9** проходит.
- `git status` — **80** незакоммиченных позиций; `scripts/` — **134** файла; venv — **3** (`.venv313`, `.venv314`, `.venv314c`) — соответствует отчёту.
- Что GLM **не** проверял (и это не его вина — он не получал P0-чеклист): immutable-политику, дрейф схем, сверку DEVLOG↔артефакты, ML fail-closed, IPC-роли, fail-safe. Это закрывает локальный субагент / human-review.

**Вывод:** это **качественная общая оценка (7,5/10 прототип), но не P0-ревью**.
