# План разблокировки P3 (F21–F26)

> Составлен по запросу «Продолжи и Разблокируй». Показывает, что именно нужно от человека для каждого пункта, что я могу сделать сразу после разблокировки и чем это подтверждается (артефакт/метрика). Пункты, которые нельзя «разблокировать словами» (права, сертификат, VM), помечены отдельно.

## 1. Что можно разблокировать прямо сейчас (без новых прав)

| Пункт | Действие | Ограничение |
|---|---|---|
| Длинный soak (F11) | запускать прогоны до нескольких часов в фоне, без расписания | суточный/7-дневный прогон требует **расписания** — это отдельное разрешение |
| Проверка drift моделей, паритет, калибровка | повторные офлайн-прогоны скриптами | нужны данные; новых данных нет |
| Промоушен модели (F26) | **только человек**: реестр отказывает агенту в `champion` | требует явного решения владельца |

## 2. Что требует прав на хосте (нельзя выдать текстом)

| Блокер | Что нужно физически | Что будет сделано после |
|---|---|---|
| D — окно с admin | запуск от администратора на этом хосте | WDAC enforce и E12 в боевом режиме, RTP Defender, ETW-TI, Windows T1055 |

## 4. Что уже сделано для E6 (rootkit) и почему «разблокировать» нельзя

E6 требует событий уровня ядра Windows (ETW-TI, callback'и) или Linux-хуков, которые
сейчас недоступны: фильтр/драйвер не подписан, элевации нет. Наблюдательные BPF-хуки
это не заменяют. Пока не появится подпись (A/B) или окно admin (D), **любая цифра E6
будет выдумкой** — поэтому пункт остаётся открытым, а не «оценённым».

## 5. Порядок, если разблокировки придут

1. admin-окно (D) — самый дешёвый и самый широкий эффект: E12 enforce, ETW-TI, Windows T1055.
2. Linux-VM (C) — IMA/fs-verity, сверка с тем, что уже измерено на WSL.
3. Windows VM + WDK (B) → подпись (A) — только после них имеет смысл писать драйвер.
4. rustup (E) — параллельно, после стабилизации Python-версии.
