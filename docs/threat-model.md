# Модель угроз

> **Статус:** норматив. Дополняет v9.1 (угрозы распределены по слоям L0–L8 и реестру окон).
> **Назначение:** единое понимание того, что защищаем, от кого и где границы возможностей.

## 1. Активы

| Актив | Windows | Linux |
|---|---|---|
| Учётные данные | LSASS, SAM, DPAPI, токены | /etc/shadow, SSH-ключи, облачные токены, env |
| Целостность ОС | системные файлы, реестр, службы | бинарники, systemd units, модули ядра |
| Данные пользователя | Desktop/Documents/Downloads | /home, БД, рабочие каталоги |
| Сам защитник | бинари, конфиги, модели, журнал | бинари, конфиги, модели, журнал |
| Телеметрия/обучение | кейсы, baseline | кейсы, baseline |

## 2. Нарушители

| Тип | Возможности | Что детектируем | Что НЕ можем |
|---|---|---|---|
| Скрипт-кидди | готовые инструменты (mimikatz, брутфорс, miners) | правила + L0 + аномалии | — |
| Продвинутый | обход детекторов, тамперинг, очистка логов, LOLBin | L1–L4 + корреляция + LLM | прямой syscalls, kernel-руткиты |
| Вредоносный инсайдер | легитимный доступ, злоупотребление | аномалии, аудит | намеренное легитимное использование |
| Администратор/root | полный контроль ОС | детекция тамперинга, журнал | **не выживаем** (честная граница) |

## 3. Векторы (по платформам)

**Windows:** фишинг → PE из Downloads/%TEMP%; макро/HTA/ISO; LSASS dump; автозапуск; очистка логов (1102); LOLBin; WMI/WinRM/SMB lateral; DNS/HTTPS C2.

**Linux:** SSH-брутфорс; веб-шелл; cron/systemd/authorized_keys/LD_PRELOAD персистентность; sudo/suid эскалация; kernel-модуль/eBPF-руткит; крипто-майнер; rm -rf/шифрование.

## 4. Границы (что НЕ покрываем честно)

- Руткиты уровня ядра, атаки на гипервизор, firmware/bootkit.
- **Администратор/root**, целенаправленно убивающий защиту: user-mode + даже драйвер не гарантируют выживание против администратора. Детектируем и логируем, не «неубиваемы».
- Физический доступ.
- Сетевые атаки на периметре (не наш контур).
- Runtime-безопасность контейнеров (host-level наблюдаемость с `container_id`, без runtime-защиты).
- Замену полноценного EDR/антивируса — мы лёгкий EDR, дополняем, а не заменяем (см. operations.md, режим `compat`).

## 5. Допущения и предпосылки

- Администратор/SYSTEM (Windows) или root (Linux) доступны для установки и работы.
- Secure Boot — поддерживаемая конфигурация; SELinux enforcing / AppArmor — поддерживаемы.
- Sysmon/auditd/eBPF опциональны; при отсутствии — документированная деградация (см. reliability.md).
- Драйвер подписан attestation/WHQL (Windows); eBPF без kernel-модуля (Linux).

## 6. Связь с реестром окон

Каждый вектор из §3 раскрывается в `docs/hack-windows-register.md` как окно: стадия kill chain → слой → механизм → верификация → метрика. Модель угроз задаёт «что и от кого», реестр окон — «как именно закрываем и проверяем».
