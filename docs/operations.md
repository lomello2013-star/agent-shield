# Операционная модель и сосуществование

> **Статус:** норматив. Раскрывает v9.1 §14.

## 1. Владельцы и роли

| Роль | Ответственность |
|---|---|
| PM | внешний критический путь (подпись драйвера), решения v9-min/v9-max, приёмка этапов |
| Security engineer (человек) | human-review драйвера (100% PR), spot-check, red-team, эскалации |
| Allowlist-куратор | L0: allowlist, разблокировка ≤4 ч, false block rate (E12) |
| Оператор клиента | установка, инциденты, обновления (в пилоте — мы) |

## 2. Сосуществование с EDR/AV

Ядро-компонент (minifilter+ELAM / eBPF) может конфликтовать с Defender/CrowdStrike/SentinelOne — реальная причина BSOD и отказов.

| Правило | Действие |
|---|---|
| Работаем **рядом**, не вместо | не заменяем EDR, дополняем |
| Режим `compat` | только наблюдение (без перехвата), если обнаружен конкурирующий драйвер/EDR |
| Приоритет | не ломать чужую защиту; при конфликте — деградация, не борьба |
| Тесты | машины с топ-3 EDR в матрице (test-strategy.md) |
| Минимальный набор callbacks | драйвер не перекрывает чужие перехваты (altitude — согласованный) |

## 3. Ресурсы пилота (без денежной оценки)

- ВМ: Windows 10/11/Server ×2, Ubuntu/Debian/RHEL/Fedora ×2, машины с топ-3 EDR ×3.
- Red-team: 20 сценариев/ОС, ~2 человеко-недели на платформу на прогон.
- Human-review драйвера: закладывается в план, а не «по мере».
- Allowlist-куратор: выделенное время в пилоте.

## 4. Инцидент-ранбук (краткий)

| Инцидент | Действие оператора |
|---|---|
| `tamper` | проверить целостность, переустановить подписанный артефакт, разобрать причину |
| `BSOD` | halt раскатки, собрать WER/дамп, откат драйвера, эскалация |
| Массовый FP | kill-switch правила/модели, откат обновления, разблокировка allowlist |
| Тихий отказ источника | проверить `degraded`, перезапустить источник, re-check прав |
| `incident` без объяснения | эскалация (SLA 48 ч) |

## 5. Allowlist-операция (L0)

- Владелец — allowlist-куратор; SLA добавления в allowlist ≤4 ч.
- False block rate (E12) мониторится ежедневно; цель <0,1% в enforce.
- Переход audit→enforce: 2 недели audit без критичных блоков + allowlist покрывает ≥99,5% легитимного.
- Откат политики L0 — одним действием (kill-switch), без переустановки.

## 6. Обновление-операция

- Dual-slot A/B; canary 1% → 10% → 100%; автооткат по health.
- Kill-switch на правило/модель/драйвер по id.
- Откат-тест обязателен перед каждым релизом.
- Журнал обновлений — тип `model_update`/`driver_review` в DEVLOG.

## 7. Сводка обязанностей при сбое

Любая потеря/деградация — событие `incident` (не тихий счётчик). Превышение error budget → freeze фич, только стабилизация.
