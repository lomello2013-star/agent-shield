# DPIA — черновик (техническая часть)

> **Статус: черновик, не юридическое заключение.** Подпись DPO/юриста обязательна.
> Документ описывает текущую реализацию STML; production-развёртывание может
> изменить состав данных и юрисдикции.

## 1. Контекст

STML — сервер флота + коннектор агента «ИИ-защитник». Обрабатываются события
безопасности, инвентарь хостов, телеметрия (opt-in), отчёты об инцидентах,
аудит действий операторов.

## 2. Категории данных

| Категория | Примеры | Где хранится | Правовой статус |
|---|---|---|---|
| Идентификаторы хоста | hostname, agent_id, connector_id | SQLite/PostgreSQL | может быть персональным (сотрудник/устройство) |
| События безопасности | process/auth/file/net события | отчёты, JSONL | может содержать ПДн (username, path) |
| Инвентарь | OS, arch, version, capabilities | agents | обычно не ПДн |
| Телеметрия обучения | features/events, opt-in | telemetry | зависит от содержимого |
| Кейсы | TP/FP, features | cases | обезличенные/агрегированные |
| Операторские токены | admin/viewer/approver | файлы/env | секреты, не ПДн |
| Аудит | actor/action/target | audit | может содержать идентификаторы |

## 3. Цели обработки

1. Обнаружение и расследование инцидентов ИБ.
2. Управление флотом (политики, rollout, изоляция).
3. Улучшение детекторов (только opt-in, с минимизацией).

## 4. Минимизация и фильтрация

- Телеметрия: **opt-in** (`consent=true`), иначе 403.
- Rust-фильтр удаляет ключи `raw`, `cmdline`, `path`, `username`, `email`.
- Python-коннектор: PII-фильтр/хеширование ID — **проверить перед production**;
  текущий черновик не подтверждает полноту.
- Сырые события не должны попадать в learning-корпус без обезличивания.
- `agent_id` — UUID; hostname может быть персональным.

## 5. Сроки хранения

| Данные | Предлагаемый срок | Статус |
|---|---|---|
| Reports/incidents | 90–180 дней | не автоматизировано |
| Telemetry | 30–90 дней | не автоматизировано |
| Audit | 1 год (или по политике) | не автоматизировано |
| Backups | 30 дней, шифрование | скрипты есть, retention нет |

Нужны решение владельца и автоматическая очистка.

## 6. Доступ и роли

- `viewer` — чтение.
- `admin` — политики/rollout/команды.
- `approver` — только approve/deny (SoD; admin не approve).
- mTLS client cert — транспортный доступ.
- Аудит hash-chain; экспорт JSON/CEF.

## 7. Риски и меры

| Риск | Мера | Остаток |
|---|---|---|
| Утечка ПДн в телеметрии | opt-in, удаление ключей | нужен полный PII-фильтр и тесты |
| Компрометация токенов | ACL, ротация, mTLS | production — HSM/secret store |
| Доступ через GUI | sessionStorage, bearer | нет SSO/MFA |
| Трансграничная передача | локальный сервер | зависит от развёртывания |
| Избыточное хранение | retention-политика | не автоматизировано |
| Повторная идентификация | UUID/хеши | hostname остаётся |
| Злоупотребление approve | SoD | нет 4-eyes для всех действий |

## 8. Права субъектов

- Доступ/удаление: через оператора; нужен процесс.
- Удаление телеметрии/кейсов: SQL/скрипт; нет self-service.
- Экспорт: audit JSON/CEF; отчёты — API.

## 9. Открытые вопросы (для юриста/DPO)

1. Правовое основание обработки событий безопасности сотрудников.
2. Нужен ли DPIA для каждой юрисдикции/tenant.
3. Сроки хранения и legal hold.
4. Трансграничная передача (если облако).
5. Уведомление субъектов/профсоюзов.
6. Обработчик/контролёр: кто владелец данных у заказчика.
7. Требования 152-ФЗ/GDPR к псевдонимизации.
