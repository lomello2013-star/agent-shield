# Журнал спорных решений (decision log)

> **Правило:** при спорном решении фиксируем варианты (A/B/C), рекомендацию агента,
> выбор и обоснование. Если человек не сказал иначе — выбирается **рекомендация
> агента**. Запись делается до/во время реализации, а не задним числом.

## Шаблон

| Поле | Значение |
|---|---|
| ID | D-XXX |
| Дата | YYYY-MM-DD |
| Вопрос | … |
| Варианты | A / B / C |
| Рекомендация | … |
| Выбор | A/B/C |
| Обоснование | … |
| Статус | open / decided / revisited |

## D-001. Ambient 7045 и правило WIN-SERVICE-CREATE-007

**Вопрос:** правило 007 срабатывает на любой service install, включая фоновые
службы Windows (FP на benign-контроле 20-среза).

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Allowlist имён служб | просто | хрупко, атакующий мимикрирует |
| B. Контекст: высокий риск только для temp/user/programdata/Downloads или не-LocalSystem | убирает ambient, ловит типовой malware-паттерн | можно пропустить service из System32 |
| C. Понизить severity/alert-only | меньше шума | теряем блокировку |
| D. Оставить как есть | ничего не делать | FP на каждом хосте |

**Рекомендация:** **B** + отдельное alert-правило для прочих service install.
**Выбор:** B (рекомендация агента), с записью компромисса в docs.
**Обоснование:** ambient-службы идут из System32/LocalSystem; malware чаще
использует temp/user/ProgramData. Потерю generic-детекции компенсируем
alert-правилом, а не молчанием.
**Статус:** implemented (regex в 007); ambient FP = 0 в 20-срезе; alert-правило
для generic — pending.

## D-002. Атрибуция вердиктов к сценариям

**Вопрос:** запоздавшие вердикты (`RUNKEY` от WIN-06 в окне WIN-08, ambient 7045
в контроле) приписываются следующему сценарию; settle-барьер не гарантирует.

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Только settle/пауза | просто | не устраняет гонку |
| B. Писать `event_id`, `ts_event`, `object_path` в audit и матчить сценарий по событию | детерминированно, пригодно для продукта | schema/audit изменения |
| C. Один сценарий на свежий экземпляр службы | чисто | медленно, не для 20/ОС |
| D. Ручной разбор audit | без кода | не масштабируется |

**Рекомендация:** **B** (+ A как защита от гонки).
**Выбор:** B (рекомендация агента).
**Обоснование:** атрибуция по времени обработки неверна; нужен `ts_event` и
`object_path` в audit, чтобы матчить действие с событием, а не с окном.
**Статус:** implemented & verified: `event_id/event_ts/object_path` + матчинг
`Get-VerdictsSince`; 20-срез 8/11, **0 FP** (WIN-08 — реальный miss, не гонка).

## D-003. Linux 20/20 live

**Вопрос:** Linux-каталог из 20 сценариев не прогнан live; eBPF-агент в Linux-VM
не установлен, хост 16 ГБ (Win11 4 ГБ, Linux VM сохранена).

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Установить Python + eBPF-агент в Linux-VM, прогнать live | настоящий live-срез | RAM/время, сборка BPF |
| B. Fixture-level 20 сценариев через rule engine | быстро | не live, нельзя выдавать за red-team |
| C. Отложить до появления RAM/упаковки | честно | нет прогресса |

**Рекомендация:** **A**, при блокере — **B** с явной пометкой «fixture-level».
**Выбор:** A (рекомендация агента), fallback B только при доказанном блокере.
**Обоснование:** пользователь просил live; fixture-level не должен подменять его.
**Статус:** A partially: toolchain + live exec trace (20 событий, ~446 µs)
проверены; production-коллектора loader→pipeline нет, 20/20 live — open.

## D-009. Классификация Defender 5007 (exclusions)

**Вопрос:** 5007 exclusion-путь классифицировался как benign, поэтому
`WIN-DEFENDER-TAMPER-009` не срабатывал (WIN-08 miss), хотя exclusion — это
T1562.001.

| Вариант | Плюсы | Минусы |
|---|---|---|
| A. Оставить benign | нет шума | пропускаем defense evasion |
| B. Добавить `exclusions\paths|processes|extensions` в suspicious | ловит T1562.001 | возможен FP на легитимных exclusion |
| C. Отдельное правило + allowlist путей | точнее | сложнее, нужен курируемый список |

**Рекомендация:** **B** + позже C для allowlist.
**Выбор:** B (рекомендация агента).
**Обоснование:** exclusion — типовой шаг атакующего; 5007 уже пишется, не
хватало только классификации. FP на легитимных exclusion допустим и виден.
**Статус:** implemented & verified: live `009 = 7`, WIN-08 detected.
