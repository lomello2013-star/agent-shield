# Rust STML server: service + healthcheck

## Windows (SYSTEM task)

```powershell
# elevated
.\scripts\install_stml_rust_task.ps1
Get-ScheduledTask -TaskName AIDefender-STML-Rust
python scripts\stml_healthcheck.py --url http://127.0.0.1:8090 --token <viewer> --require-agents
```

- Task `AIDefender-STML-Rust`, startup, restart 3x/1 min.
- Config: `C:\ProgramData\AIDefender\stml\rust.env.json` (ACL; contains tokens).
- Binds `127.0.0.1:8090` by default (Python reference keeps 8080).
- DB: `stml_p4`; `STML_TENANT=default`.

## Linux (systemd)

- `deploy/systemd/stml-rust.service`
- `/etc/stml/rust.env`: `DATABASE_URL`, `STML_BIND`, tokens, `STML_TRUST_DIR`,
  optional `STML_POLICY_PUBKEY_FILE`, `STML_TENANT`, TLS/CRL vars.
- Binary: `/opt/stml/rust/stml-server`.

## Healthcheck

```powershell
python scripts\stml_healthcheck.py --url http://127.0.0.1:8090 --token <viewer> --require-agents
```

Exit 0 only if `/health` ok and `/v0/agents` returns a list.

## Notes

- Rust task is separate from the Python reference; do not bind both to 8080.
- `tokens.json` is generated by the Python server; the Rust task reuses its
  admin/viewer/approver tokens. Rotate both services together.
